# 来源与证据政策

## 证据等级

### verified

在固定提交和具体源码路径中能定位到对应角色、依赖方向或算法，并有行为或测试证据。示例：`TypedEventBus` 对应 deepseaoil 的强类型事件通道。

### adapted

真实项目提供了问题与核心结构，但本仓库重新设计了类型、边界或算法细节。示例：流场去掉 Unity 净空采样，只保留网格、步价、方向和缓存。

### concept-only

复盘、架构目标或术语中存在该思想，但源码没有严格完整的模式角色。示例：存档是版本化快照，借鉴 Memento，但不能称为严格 Memento。

## 声明要求

每个模式声明至少回答：

1. 变化点是什么？
2. 哪些角色协作？
3. 依赖方向怎样变化？
4. 代价和不适用条件是什么？
5. 固定源码或测试证据在哪里？

## 禁止做法

- 按类名猜模式。
- 用模式数量衡量架构质量。
- 把业务实现细节包装成通用规律。
- 把尚未完成的设计目标写成当前事实。
- 在公开文档中写入个人电脑绝对路径、私有配置或未授权材料。
